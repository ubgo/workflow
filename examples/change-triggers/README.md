# change-triggers

Turn row changes of an app table into jobs with a trigger generated by `outbox.ChangeTrigger` (SQLite in memory): an insert, an update and a delete made by plain SQL each write an outbox entry carrying the chosen columns (never `password_hash`) and the operation, and the relay delivers the three jobs to the memory driver.

```sh
cd examples
go run ./change-triggers
```

```text
-- install the trigger
statements: 6
-- change rows with plain SQL
-- relay to the workers
relayed: 3
synced {"id":"a1","email":"ana@example.com","plan":"free","op":"insert"} true
synced {"id":"a1","email":"ana@example.com","plan":"pro","op":"update"} true
synced {"id":"a1","email":"ana@example.com","plan":"pro","op":"delete"} true
```

On Postgres pass `sqlb.PostgresDialect{}` (a plpgsql function plus one trigger, Postgres 13 or later) and on MySQL `sqlb.MySQLDialect{}` (one trigger per operation); the program is otherwise the same.

The guide [Database change triggers](../../docs/reliability/change-triggers.md) explains each step. `main_test.go` runs the same program and checks every line above.
